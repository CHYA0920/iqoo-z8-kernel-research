# 研究地图

已公开研究阶段(0 → 3.1)的完整节点地图。每个节点携带:闭环条件(在认证它的实验之前书面写定)、运行时判据(认证它的可观测信号)、实测证据(连续通过判据的轮次数)。

节点状态词汇:

- **STABLE(已敲定)** —— 闭环条件预先定义;运行时判据连续至少三轮通过;复现路径已文档化;机制级(在更高阶段重设计后仍然成立)。
- 静态分析结果可以支撑设计,但永远不能把节点标为 STABLE。

## 节点详表

### [0.1] 构建与部署流水线 — STABLE
- **闭环条件**:改码 → commit → CI 构建 → 产物下载 → 设备部署 → 测试启动,全链无人工干预。
- **判据**:preflight 打印所下载产物的 SHA256,与 CI 产物身份一致,随后出现轮次启动行。
- **实测**:连续十四轮全自动(r53-r66 谱系)及后续验证批。
- **复用性**:机制无关;流水线对后续阶段无任何假设。

### [0.2] TCP 微秒级探针通道 — STABLE
- **闭环条件**:设备侧 harness 经 adb reverse TCP 连回主机,每个阶段标记在主机侧探针日志留下带时间戳的行。
- **判据**:每轮标记链——连接、早期里程碑、payload 就绪(HELLO)、触发(FIRE)——全部在场。
- **实测**:r53-r66 谱系每一轮及后续全部批次,含内核在 fire 段后死掉的轮次(通道存活足够久,足以上报)。

### [0.3] O_DSYNC 诊断落盘通道 — STABLE
- **闭环条件**:harness 诊断以 O_DSYNC 写出,每次写在下一条语句执行前落盘。
- **判据**:轮末内核 panic + 设备重启后,诊断文件仍可拉取,且包含死前写下的每一行。
- **实测**:r53-r66 谱系每一轮 T+120s/T+180s 双拉取成功。

### [1.1] KASLR text 基址 — STABLE
- **闭环条件**:非特权 perf_event_open 采样喂入时序直方图,从中推导内核 text 基址;专用门限标记计算接受/拒绝该推导(分数阈值 0.5)。
- **判据**:门限打印显式判决行;只有 PASS 判决允许轮次继续。
- **实测**:连续十四轮分数 0.905-1.000 全 PASS;多采样投票设计下(见 [02-information-leak.md](02-information-leak.md))验证批达 100%。
- **复用性**:与更高阶段的设计决策正交。

### [1.2] 内核符号锚族 — STABLE
- **闭环条件**:从 [1.1] 披露的地址出发,以固定差值偏移(符号间差为构建常量)推导所选 .data 符号地址,而非读 kallsyms(本设备受限)。
- **判据**:每轮几何日志行打印推导出的 task/text 值,与差值预测一致。
- **实测**:锚定算术锁定后(早期修正之后)每轮核对通过,贯穿 r53-r66 谱系与后续批次。

### [1.3] 物理页披露与受控 staging — STABLE
- **闭环条件**:泄漏原语披露支撑内核分配的物理页;该页随后被准备为用户侧完全控制内容的 staging 区。
- **判据**:harness 打印已准备页的泄漏基址;后续验证回读 staged 内容。
- **实测**:谱系每一轮成功(地址随 KASLR 变化;语义不变)。
- **复用性**:与更高阶段机制无关。

### [1.4] 喷射驻留 — STABLE
- **闭环条件**:经 unix-socket order-3 喷射族放置并驻留 16 个有序 sk_buff 分配(各 65,536 字节)。
- **判据**:全部 16 次发送报告 65536 字节接受。
- **实测**:每轮 16/16。

### [2.1] futex PI chain-1 EDEADLK — STABLE
- **闭环条件**:在构造链上执行 FUTEX_CMP_REQUEUE_PI 返回 -EDEADLK(errno 35),回滚在目标字上留下 WAITERS 位。
- **判据**:errno 35 + 目标字 after 值带 WAITERS 位,harness 双打印。
- **实测**:每轮。

### [2.2] chain-2 / chain-3 环闭合 — STABLE
- **闭环条件**:第二条 EDEADLK 链经 WAITERS 位握手闭合 waiter 环,使最终重定优先级 walk 有确定性的 walk 前状态。
- **判据**:chain-2 每轮 errno 35;chain-3 errno 35 + 被阻塞 waiter 从 requeue 醒来。
- **实测**:首次闭合的轮次之后,每轮复现。

### [2.3] 树 stamp 原语 — STABLE ★
- **闭环条件**:32 位任务调用 setsockopt(IPPROTO_IPV6, MCAST_JOIN_SOURCE_GROUP) 携 260 字节缓冲,将该缓冲逐字节写入调用任务内核栈深处的固定槽位。
- **判据**:harness dump 目标栈区 32 qword,与构造 payload 逐字节一致。
- **实测**:谱系每一轮。
- **复用性**:原语域明星资产——该机制使 [1.3] 的 staged 几何得以放置到后续 PI walk 读取的位置。

### [3.1] fire → PI walk 执行并返回 — STABLE
- **闭环条件**:环头任务的 sched_setattr 重定优先级触发优先级继承 walk;walk 跑过 staged 几何,完成,控制权返回用户态。
- **判据**:harness 打印触发返回码;ret2 = 0 为通过线。
- **实测**:r53-r66 谱系十八轮每一轮,及后续全部验证轮。
- **注意**:"walk 跑完"与"walk 后果良性"是两个不同的命题;公开边界是前者。后果分析不在本仓库范围内。
