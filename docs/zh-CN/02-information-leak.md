# 阶段 1 —— 信息泄漏域

四项能力,全部纯读,全部让系统保持健康。合起来回答:内核在哪、我们关心的对象在哪、能在哪 staging 受控数据。

## [1.1] 基于 perf_event 采样的 KASLR text 基址

内核 text 基址从非特权 perf_event_open 时序采样披露。perf 侧信道 KASLR 披露的总体思路在文献中已知;这里的工程贡献是可靠性。

**单锚陷阱。** 锚定在单采样点上的推导在可测比例的启动上概率性出错。更糟的是,错误推导并不明显错误:推导出的基址可以偏差兆字节级,却仍是一个看起来合理的内核地址。错误基址会静默污染后续每一个地址计算。

**投票修复。** 工具族(exploit/src/kernelsnitch/)取多个独立采样,推导候选基址,投票。只在决定性多数下轮次才继续。实测结果:

- 连续十四轮门限判决 PASS,分数 0.905-1.000;
- 采用投票后,验证批次通过率 100%。

**采样纪律。** 采样侧还执行批次节奏控制:waiter 线程以有界批次孵化,批间以遍历时间探针(128x FUTEX_WAKE_BITSET,互斥 bitset——纯时序,零真实唤醒)测桶深,遍历时间超基线倍数即提前退出。这防止采样过程本身失稳被测系统。

## [1.2] 差值式内核符号锚推导

本设备 kallsyms 不可读(kptr_restrict)。符号地址改由披露锚 + 固定差值推导:符号之间的偏移是构建常量,知道一个锚地址即可加法求出其余。

- 输入:[1.1] 的 text 基址与实测锚地址。
- 输出:后续阶段推演所需的所选 .data 段符号地址。
- 判据:每轮几何日志打印推导值;锚定算术锁定后每轮与差值预测一致。

这是受限 kallsyms 环境下的通用技术,也是整个计划从不需要读符号表的原因。

## [1.3] 物理页披露与受控 staging

泄漏原语披露支撑内核分配的物理页。披露页随后被准备为 staging 区:用户侧控制该页全部内容。harness 每轮打印页基址;验证回读 staged 内容。

它买到的东西:一块内核可见、内容完全由研究者指定、地址已知的内存。公开边界止于该 staging 区在阶段 2/3.1 walk 几何之外的任何消费者之前。

## [1.4] 喷射驻留

十六个有序 sk_buff 分配,各 65,536 字节,经 unix-socket order-3 喷射族放置并驻留。判据:全部十六次发送报告 65536 字节接受——每轮实测 16/16。

用途:堆形状控制。驻留的喷射对象钉住后续阶段推演所依赖的分配器布局,使 [1.3] staging 的几何在阶段 2/3.1 的时序窗内保持不动。

## 本域为何重要

[1.1]-[1.4] 是纯读加堆整形:前后系统健康且完全相同。它们也是机制无关的地基——这里的一切对后续阶段如何消费披露信息零假设,因此整个域在之上一切重设计后仍然成立。
