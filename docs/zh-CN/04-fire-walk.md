# 阶段 3.1 —— fire:PI walk 执行并返回

本仓库的公开边界。这条线之前的一切是准备;本阶段是内核消费已备几何,并证明它这么做且活着回来。

## 触发

对环头任务的 sched_setattr 重定其优先级。按 futex 优先级继承语义,一个在 PI 链上被阻塞的任务被重定优先级,会强制内核走链:沿 waiter 结构向上调整优先级,重平衡 waiter 树,把变化传播过 [2.2] 闭合的环。

触发 syscall 在 shell 域的可达性由公开的 sched_test 探针验证(单 syscall,定界结果块)。探针存在的意义正是让这个命题无需任何未公开 harness 即可查验。

## "fire" 的力学含义

触发时刻:

- [1.1] 已定内核 text 基址(投票击败 KASLR);
- [1.2] 已推导 harness 推演所需符号地址;
- [1.3] 已在已知内核地址 staging 完全由用户撰写的页;
- [1.4] 已钉住其周围堆形状;
- [2.1]/[2.2] 已以可观测中间状态闭合确定性 waiter 环;
- [2.3] 已把逐字节精确内容 stamp 到 walk 将遍历的深栈槽。

触发即请求内核 walk。walk 从 stamped 栈区与 staged 页读取几何,执行优先级传播,完成,控制权返回用户态。

## 判据

harness 打印触发返回码。**ret2 = 0 为通过线**:walk 跑完并返回。

- **实测**:r53-r66 谱系连续十八轮,加后续验证批每一轮。

## 本阶段主张与不主张什么

"walk 跑完"是一个精确、有边界的命题。它是公开里程碑:内核侧消费用户撰写几何,干净返回,可复现。

它刻意不覆盖:

- walk 对 staged 几何邻接对象的后果;
- 任何后续阶段,任何方向。

仓库在此止步。边界不是修辞——代码物理切在此处,构建系统不构建两个可达性探针之外的任何东西,未公开阶段所需的符号/偏移表不在树内。

## 为什么以这里作为公开终点

阶段 0-3.1 构成自洽、各自可验证的语料:测量基础设施、信息披露、逐字节写原语、内核侧对撰写状态的已证 walk。每件都可用同型号设备加公开探针被第三方独立查验。该语料独立具备防御价值——它演示的每个阶段都是加固内核应当封死的面,而方法论超出本链路通用。
